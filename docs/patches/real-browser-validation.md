# 网页流程修复与验收边界

## 修复范围

- 一键动态项目由工作站持久化推进，用户离开制作页后继续处理。只接管明确选择一键制作的任务；提交结果未知或失败时暂停，保留原任务凭据，避免重复付费。
- 采用 Qwen 设计声音期间锁住关闭和引擎切换操作，等参考音频传递完成后再解锁。
- 字幕以实际音频时长为边界，防止识别器的异常尾部时间戳产生很长的静止尾镜。
- 新建动态项目使用中性题材默认，允许恢复账号保存的图像服务及本地视频工作流，不再盲选第一个工作流。
- 图像与视频默认配置分别应用：图像选择器先完成初始化时，不再丢弃稍后返回的视频工作流；手动修改的视频选项仍优先保留。
- 镜头参考信息仍在读取时禁用依赖它的生成操作；避免按钮可点击却被内部检查挡住。
- 局部重做后根据当前项目状态显示成片尚待更新，避免继续显示上一次导出的“已完成”；不会因为查看状态而自动重新生成。
- H3 中文声音指令按局部谓词判断否定，允许“也不生成对白”等自然写法，同时拒绝相邻的肯定指令和双重否定。保留诊断草稿，输入未变时可重新校验，避免无谓重调语言模型。
- 修复“无说话口型、对白、旁白”等禁止语音描述被误判的问题；环境声不受影响，相邻肯定指令和双重否定仍会被拒绝。

## 复验方法

使用真实部署网站和新浏览器，从页面登录并创建新项目。经网页采用声音、选择风格、启动制作，然后返回首页、刷新和切换项目。项目的新角色、配音、图片、视频、合成必须由正常流程产生。每次手动恢复都记录，不能计作一次无干预的一键成功。

`frontend/scripts/verify-workbench.mjs` 提供可复用的桌面、手机网页检查。报告记录实际入口脚本，可用 `OCV_TEST_FRONTEND_BUNDLE` 约束部署版本。此检查不会生成媒体，报告始终保留 `mediaGenerationVerified: false`；使用方式见同目录 `README.acceptance.md`。

## 仍需区分的结果

单元测试通过、网页按钮可用、文件成功导出、成片质量合格是不同结论。成片还须检查：故事是否有观看动力、角色和道具是否连续、动作是否达到指定位置、字幕配音是否同步，以及是否出现非预期人声或背景音乐。没有 ASR 转写不能证明没有音乐或人声。

已知示例中仍出现过角色左右位置跨镜变化、跑姿循环但位移不足，以及明确禁止人声后 H3 仍生成疑似无意义语音。提示词约束不能保证生成模型完全遵守；这些问题未被代码测试证明解决。语音识别目前是独立验收脚本，尚未接入网页自动质量关卡。当前修复不等于多题材成片质量已经通过验收。
