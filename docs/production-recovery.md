# 生产中断后如何继续

适用于故事创作、动态分镜和视频制作。无需编辑数据库、删除缓存或重新创建项目。

## 先看“生产问题处理”提示

选择失败镜头。页面会显示问题说明、具体原因及对应操作；已完成的镜头和原图保留。

| 问题 | 网页操作 | 会不会重新调用模型 |
| --- | --- | --- |
| 开场对接、JSON 或字段校验失败 | “重新分析本镜并继续” | 明确确认后重新分析当前镜头，通过后生成当前镜头视频；失败即停止 |
| 图片缺角色、道具，或动作与图片冲突 | “检查并修改本镜图片与动作” | 打开编辑不收费；重画、更新提示词或视频生成才调用相应服务 |
| 缺少已采用音色 | “去角色与音色设置” | 选用已有音色不重新设计；也可明确选择模型自生成 |
| 连接超时、鉴权、额度、GPU 或工作流问题 | “打开接口与服务” | 查看设置不生成；恢复服务后继续未完成步骤 |
| 原视频任务状态未知 | “继续查询原任务” | 查询已有任务，不提交新任务；无法续查时需核实服务端结果 |
| 图片未完成 | 打开本镜，重试单镜图片或上传替换 | 上传不调用模型；重新生成图片会调用图片服务 |
| 分镜规划未完成 | 继续未完成规划或修订并重试规划 | 会调用语言模型；有可用检查点时复用已完成阶段 |
| 合成失败 | 回到“合成与导出”，处理磁盘/FFmpeg 问题后重新合成 | 不重做镜头，不调用生成接口 |

“重新分析本镜并继续”不是关闭质量检查：原台词、角色、音色、图片和时长保留，仍然检查缺角色、重复角色、错误口型归属和动作时序。旧失败分析留存，新分析使用独立尝试编号；普通重试不会暗中无限重跑语言模型。

同一角色 ID 的站位返回顺序不同、已知画外旁白多了一条无效站位、动作/发言可见性数组顺序不同，程序会按 ID 与时间整理，不为这种格式差异额外调用模型。

## 修改范围

- 修改图片：进入“重新编辑本镜”，选择上传或重绘；其他镜头保留。
- 修改动作：编辑动态表达后主动更新提示词；若涉及时长，可用“本镜二次编辑”先预览建议再采用。
- 只换图或声音且保留提示词：采用新素材后重新生成本镜，不需要重新规划全片。
- 只需取回已有视频：使用查询原任务；不要选择新的生成。

一键任务仍在运行时，先暂停或等当前操作结束再编辑。远程模型未安装、显存占用、服务欠费或断网需要部署者处理实际环境，网页不能凭空补齐这些条件。没有模型辅助也可以手动编辑、上传图片或替换视频；AI 建议和重试不保证输出质量合格。

## 开发入口

- `frontend/src/productionRecovery.js`：错误分类与建议动作，无网络或状态写入。
- `frontend/src/components/ProductionRecovery.vue`：统一恢复卡片。
- `frontend/src/components/VideoStudio.vue`：导航和用户明确确认后的操作。
- `backend/app/video_studio.py` 的 `retry_shot_preparation`：账号隔离、版本检查、原任务状态保护与单镜尝试编号。
- `backend/app/video_native_grounding.py`：按 ID/时间对接及缓存隔离，不改变故事资产。
- `tests/test_video_recovery.py`、`tests/test_video_native_grounding.py`、`frontend/tests/productionRecovery.test.mjs`：恢复边界回归。
