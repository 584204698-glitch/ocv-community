## 官方依据

[官方 README](https://github.com/MiniMax-AI/MiniMax-H3) 说明 Context-IR 对质量重要，托管服务预处理并未完整开源。
[官方提示词 skill](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/SKILL.md) 及其 ref-en 参考提供六段式结构、声音引用和说话结束后闭唇恢复下颌的示例。本次沿用英文结构与动作描述，中文台词逐字保留。

## 本次落地

- 首轮规划和显式二次编辑共用 H3 动作、时长规则，并升级缓存版本。
- 已采用的音频参考作为声线依据，不再并列发送可能过期的角色音色描述；无参考的自主声音仍保留音色描述。
- 可见说话者每句结束后明确闭唇、下颌回静止；画外音不要求新增可见嘴部。继续原有动作，不增加台词。
- 二次编辑新增“填入 H3 表达优化意见”：只填意见，用户点击检查才调用语言模型，预览后选择采用。没有新增自动收费分析或新的硬性阻断。
- 不自动更换核心图、删除台词、增减镜头或静音覆盖异常语音。已有图片包含错误状态时，单改视频提示词可能不足。

## 用户重新测试

1. 刷新网页，在动态视频步骤选中有问题的镜头。
2. 展开“全片动态方案二次编辑”，点击“填入 H3 表达优化意见”，确认范围是本镜，再点击“检查本镜并预览建议”。
3. 核对建议台词、时长和动作；采用所选建议，再手动重新生成本镜。只直接重生成可获得编译器的新声线/闭嘴规则，但不会自动重规划原来的动作方案。
4. 如果建议指出核心图已包含未来状态、重复肢体或错误主体，应先局部修正核心图，不能用动态提示词掩盖。
5. 检查是否多词、谁开口、音色、道具和身体变化。自动语音识别不能证明说话者和画面正确，不能替代试听与观看。

## 修改位置与验证范围

`backend/app/h3_dialogue.py`：声音引用、发言终点；`video_timing_policy.py`：共用动作规划规则；`video_native_story.py`、`video_dynamic_review.py`：规划版本；`frontend/src/components/NativeProjectRevision.vue`：用户优化入口。

程序测试及部署成功不代表实片验收通过。已有第四镜的识别结果提示台词之后存在额外语音，但识别出的具体异常词句可能不准确。

## 2026-10-10 提交提示词精简

编译器 v15 删减逐段重复的静默、环境声及收尾要求；环境声只在声音章节完整列出，台词、说话者、图片与音频编号以及动作时序保持原样。单一运镜规则约束整镜连续拍摄：只执行明确规划的运镜，否则固定机位、焦距、构图及主体大小，不追加切镜和拉远。它不限制明确规划的角色位移。

同素材、同声音、同种子和采样配置的三段实片对照已完成：第一镜2841→2459字符，仍在约3.92秒跳变景别；第九镜6740→5324字符，“真的吗”仍识别为“省得吗”；第九镜3131字符的更短实验版检出额外语音、疑似错字。实验素材独立保存，不替换项目已采用视频；更短实验版不作为默认编译器。字符数减少不等于质量提高，不能据此把错音直接归因于提示词长度或所谓模型幻觉。ASR不能证明说话者、声线或口型正确。

## 2026-10-10 开场图 Guide 与参考选段

Ref2VA 预设新增“用核心图定位开场画面”，在 ComfyUI 工作台编辑预设后保存即可。服务器必须支持原生 `MiniMaxH3AddGuide` 及相应条件布局；缺少时会明确提示关闭选项或升级。此选项默认关闭，验证站当前常用预设已经通过网页启用。

启用后，后续新提交用核心图作为第 0 帧软 Guide，同时保留本镜角色图、音色和原采样 latent。已有视频与已提交任务不自动重写；只重新生成本镜即可应用选项，不必重新规划台词。软 Guide 不能保证全片像素不变。

参考声音改为最长 5 秒、优先在 2 秒之后的低能量停顿处结束，保留原采样率及原采用文件。只做 PCM 选段，不调用语言模型；停顿不是语义句尾证明。

当前实片验证显示开场片构图较稳定、未再观察到原意外切镜；双人对白仍有疑似错字，尚未通过说话者、声线及口型验收。继续使用 H3 生成对白，不以预生成 TTS 台词替代。完整证据及社区方法边界见 [研究记录](h3-community-root-causes-20261010.md)。
