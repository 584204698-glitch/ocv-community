# H3 社区反馈与通用修复决策（2026-10-10）

## 结论

目前不能把错词、额外语音、分身、衣物变化和意外切镜都归因于提示词太长，也不能把反复换种子视为根治。它们分别涉及音色参考条件、多人条件分离、画面软参考、动作与时间规划，以及某些实现错误。修复应作用于所有项目的生成链路，不针对当前故事改字补洞。

已完成的同素材、同种子对照：提示词缩短约21%后仍出现错词；进一步缩短约54%的实验版出现额外语音。固定镜头的精简提示仍出现意外切镜和被子变化。上述结果只否定“缩短就能解决”的简单解释，不证明提示词完全没有影响。用户实际听辨优先于自动识别结论。

研究阶段只读取公共反馈、文档、现有提交图和服务器源码。随后按以下兼容验证结果做最小范围的原生 Guide 接入，新增两段有明确变量的视频验证；没有安装整套导演插件。

## 对当前实现的核对

对现有两人对话提交图的读取确认：

- MiniMaxH3ReferenceToVideo接收3张图、2段声音，使用正确点号键和独立LoadImage/LoadAudio节点；提交图中有参考连接，不是只在页面显示采用。
- 一个SamplerCustomAdvanced、一个视频解码、一个音频解码和一个保存节点；没有EasyCache、二采或后期把多个生成片段拼成当前单镜。
- Sol注意力节点存在。这与EasyCache复用残差不同，社区EasyCache报告不能当作Sol故障证据。
- 运行服务器H3音频VAE的process_input是恒等处理；参考编码按真实输入采样率重采样到32kHz。没有看到相关旧版中心裁剪路径。
- 固定前5秒音色截取会在句中截断某些参考录音。这是通用流程的风险点，尚未证明就是错词根因；若调整应按句尾选择稳定短片段并固定资产版本，不能对某个故事临时换参考。

“连接正确”只排除了明显接口写法问题，并不能证明网络内部对多人条件始终正确分离，也不能证明每次声线或音素正确。

## 下一步收口方式

1. **先分离问题，不重写整个故事。** 旁白继续独立合成；H3只接收本镜发言角色的音色，不把旁白当作人物条件。准确台词、多人声线和画面构图分别定位。
2. **提示词规划只做必要减法。** 一个镜头只承担明确动作和可容纳的对话；去除与核心图冲突的动作、想象实体及重复描述；不删改采用稿的台词。参考、说话者、台词和时段只保留一致的声明，不能继续堆叠相互冲突的禁令。
3. **优先研究实际约束接口。** 对画面先检查原生Guide/关键帧能力及当前单镜适用性；对准确对白研究原生AV音频锁。只读代码确认输入、mask和调度兼容后，才决定最小集成范围。不要整套替换导演插件或把作者宣传直接当作本项目验收。
4. **保留H3原生对白路线。** 若音频锁必须使用预生成台词，应作为明确可选的新路线说明来源；不偷偷用IndexTTS替代用户要求的H3出对白。若以H3先生成台词候选再锁定，也需先验证是否节约成本及多人绑定，不预先承诺有效。
5. **停止无上限抽卡。** 只在有明确变量和预期结论时做小规模对照；同一错误在固定条件下重复出现时停止整片重跑。重试不能伪装成修复，自动识别通过也不能代替听辨与画面检查。

当前没有证据证明已根治，不发布通过声明。代码修复以通用链路为单位；视频测试以验证机制为目的，已有素材和实际提交记录复用，不再复制大量失败成片。

## 本轮实施结果

- 音色截取改为`qwen-pcm-quiet-boundary-5s-v2`：最长5秒，在至少2秒之后优先选择连续至少120毫秒的低能量停顿；没有清晰停顿则保留旧的长度上限。短录音原样保留，不重采样、不变调、不改变原始采用文件。停顿检测不是语义句尾识别，不能保证没有词间截断，也不能承诺解决H3错词。
- 校验与实际提交共用同一选段函数，选段策略版本、实际时长、边界类型与内容哈希进入原有参考记录。已生成视频和已保存提交记录没有重写。
- 现有两份原始音色的只读实测：一份从固定5秒改为4.50秒的停顿处结束；另一份5秒处本来安静，仍保留5秒。单份处理约0.024–0.025秒，不调用模型，临时验证WAV自动清理。
- 60项相关测试通过，包括PCM采样率/位宽/声道保持、字节不变、稳定选段、角色绑定及独立旁白兼容。部署到远程工作台；部署检查显示配置、项目文件及数据库内容均未变化。
- 远程当前`nodes_minimax_h3.py`没有`MiniMaxH3AddGuide`；`PackedLayout`仅支持首尾关键帧。当前官方源码有原生图像/音频Guide及任意位置支持，不能只复制一个新节点就当作完整升级。
- 旧版`model_base.py`中，参考图的`cond_video_latents`赋值会覆盖前面关键帧的同名列表。这使“旧版本直接同时塞参考图和Guide”的草率接法存在布局不一致风险。当前任务没有Guide，不据此认定它是现有画面失败原因；它是接入新约束前必须处理的兼容差异。

以上为接入前的运行环境差异。后续已经完成原生 Guide 的局部兼容移植，具体结果如下；音频锁仍未接入，不能与软 Guide 混为一谈。

## 原生开场图约束：实施及实测

- 仅移植 ComfyUI 三个文件中原生 Guide 所需的节点、参考时间布局及条件拼接变化；不替换采样器、注意力实现或整套运行环境。可复现补丁见 `patches/h3-native-guide-compat.patch`，CPU 兼容验证工具见 `scripts/check_h3_guide_compatibility.py`。
- 兼容验证包括旧布局、旧首尾帧、微型模型旧路径输出一致，以及参考图、参考音色和 Guide 共存时的有效前向。实际运行仍经原 GPU guard；只增加已验证的原生 Guide 节点白名单，保留其他准入规则。
- OCV 的 Ref2VA 预设新增“用核心图定位开场画面”选项。它将核心图作为第 0 帧 Guide，不删角色图或音色，不改变采样 latent。保存及提交前检查服务器节点能力；不支持时明确提示升级或关闭选项。其他输入模式与默认关闭时的旧图保持原路径。
- 开场片对照：相同素材、提示词、种子和采样参数，仅增加图像 Guide。8 秒片段中未再观察到先前约 3.9 秒的切镜，被子覆盖和构图较稳定。自动场景检查未检出阈值 0.20 以上事件；这不是全片画面或声音质量保证。
- 双人对白对照：增加图像 Guide，同时把一份参考音色改为 4.5 秒停顿处结束；其他条件不变。画面较稳定，但预期“真的吗？”仍被识别为“省的吗”。这是两个变量的集成验证，不能据此单独归因，也不能声称解决准确台词。
- 两段均保留 H3 原始音轨。旁白片的识别为空不能证明没有异常声音；对白片的说话者、声线和口型仍未完成验收。可播放结果在本地 `成片/H3开场图约束验证-20261010/观看.html`。

用户已明确选择继续只用 H3 生成对白，不新增 IndexTTS2.5 精确对白路线。后续对白研究保留这一要求；不以 TTS 覆盖错词，也不把音频软 Guide 描述成严格音频锁。完整多人纯对话及混合故事的一键制作验收仍未完成。

## 后续定位：单角色音色条件及嘴部可见性

仅取消第二位角色的音色参考及对应提示声明，保留第一位角色音色、原台词、时序、种子、画面和 Guide，新增一次独立诊断。识别仍为“我梦见了一片竹林省的吗”。这没有支持“第二位角色自己的音色参考是唯一原因”的判断；第一位音色仍在，不能推断全部参考都无影响。该诊断不修改项目的采用音色，不作为固定声线交付结果，也不启动重复抽卡。

发现并修复了明确的编译器语义错误：`mouth_visible=false` 原先被翻为“角色从藏身处说话，脸与嘴都遮住”。字段实际只说明嘴部不可见，角色可能没有嘴、嘴被构图裁掉或单独被遮挡，并不意味着人物或脸隐藏。v16 改为声音仍来自指定角色、没有可见嘴部运动、保留原计划身体和面部的可见范围；不编造藏身处，不改台词或入画动作。回归覆盖普通遮挡及稍后入画的无嘴机械角色，相关 111 项测试通过。这个修改不等同于错词问题已解决，尚未进行 v16 的新增实片验收。

## 用户要求的换种子对照

用户指出网页重生成本来就随机换种子，历史抽卡并不稳定。核对代码确认：重新生成使旧请求失效，并在冻结新尝试时生成新随机种子；继续查询已提交任务才保持原种子。此前固定种子是研究对照设置，不能用来解释用户全部历史重生成。

按用户要求只换一次种子：3605452218212605529 → 6906526118445117436。实际提交图逐字段比对，仅 RandomNoise.noise_seed 不同，两位参考音色、所有画面、台词、时序和提示词都保留。10.125 秒新片仍识别为“我梦见了一片竹林省的吗”，没有消除疑似错音。该结果削弱了“只因同种子重复”的解释，但一个新种子不能证明所有种子均失败，ASR仍不能替代实际听辨。

为了只检验种子变量，此片沿用原提交提示词，没有混入 v16 的转换修改。新任务成功与对白验收是两回事，不将本片写回用户项目或启动额外抽卡。

## 2026-10-10 短句能力诊断与独立识别

用户要求不再发送已知失败片，继续查根因。新增两次短诊断，输出留在远程研究目录，不复制到本地成片目录、不写回项目、不提供新的失败播放链接：

1. 仅一个可见角色说原句“真的吗？”，保留原角色图、音色、核心图、种子、采样及 Guide；去掉机械同伴和递瓶动作，规划 4 秒，实际帧网格输出 4.458333 秒。Whisper 识别“涮的吗”，Qwen3-ASR 识别“算的吗”。这是多变量的简化能力诊断，不能单独证明多人条件是原因，也不证明 H3 普遍不会说这句话。
2. 在上项基础上，仅取消唯一参考音色及其声明，H3 原生出声；其余图、种子、台词、时段与采样不变。Whisper 识别“瘦的嗎”，Qwen3-ASR 识别“送的吗”。说明在这组条件下取消全部音色参考也没有得到可用结果。不能推广为音色参考对所有片段都无影响。

Qwen3-ASR-1.7B 在远程 CPU 四线程上运行，不加载本机 GPU，不提供目标台词作识别提示。对原双人片及新种子片，Qwen 都识别为“我梦见了一片竹林，省的吗？”，与 Whisper 对关键错音一致。两套识别的共同疑点提高了发音异常的证据强度，但不是人工听辨、声线或口型验收；单人两片的具体错词互有差异，不把识别文字当作唯一实际读音。

官方 README 声明中文属于支持语言，现有 `<d>[Chinese] 真的吗?</d>` 和说话者/音频编号符合官方 skill。没有证据支持“模型无法理解这句话”这一简单结论。当前没有找到可部署的发音修复；后续应优先比较生成实现及采样/音频条件数值，复用此前 CPU 编码一致性、VAE往返及关闭Sol/加步数组合的记录，避免把失败方案反复重跑。

诊断边界：4 秒计划符合提示词 skill 的 4–15 秒建议，但原生节点的说明把约 5 秒列为训练范围下界；原 10 秒双人片同样错音，因此短诊断不能作为排除所有时长因素的证明。既有 50 步/Euler/关闭 Sol 的试验同时改变多个变量，亦不能单独证明 Sol 不影响音频。未静音覆盖、不改原稿、不增加拼音硬编码、不放宽验收。
