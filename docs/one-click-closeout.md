# 一键制作收口策略

## 自动检查边界

新建项目勾选“一键制作”时，后端会写入 `quality_review_policy=media`。它启用媒体检查，同时把原稿动机、结局表达等主观建议保留为提示，不为这些建议反复改稿。显式 `strict` 的旧项目保持原严格策略。相关代码仍需完成远程部署与实片验证，不能把本地改动视为生产环境已生效。

自动处理只覆盖格式和可定位的非视觉问题：结构化 JSON 重试、已知时长边界、外部配音时间对齐、不可见道具状态同步。角色增删、说话者或音色冲突、异常台词、分身/变形、口型和声线不能安全自动修复，仍会暂停并要求局部重做。系统不会无限重试，也不会删改原稿来“通过”检查。

## 旁白与空档

旁白仍走独立 TTS 合成，不提交给 H3。系统按实际音频长度重排已有旁白窗口，保留必要停顿，不会凭空编造旁白去填空。用户要求的“覆盖更多空档”指音轨占用时间，不等于提高音量；需要增加叙事内容时，应在原稿或旁白段落中明确增加，再重新合成对应镜头。外部 TTS 路线的环境声保留还需单独核实，当前不能宣称所有路线都保留了原环境音。

## Sol 与 Luna

Luna 可用于低风险任务：故事拆分、普通时长估算、旁白整理和分组。复杂多人对白、跨镜头状态修复、动态 H3 提示词和质量问题复核仍建议使用 Sol。当前版本不会自动把 Sol 降级到 Luna；降低模型后必须依靠结构校验，格式错误会重试，语义和视觉质量不能保证与 Sol 相同。

## 用户操作

一键运行时无需逐镜干预。若状态变为“暂停”，先按提示处理对应镜头，再点击继续；已完成镜头不会自动重建。质量检查是定位工具，不代表已经通过口型、声线或艺术质量验收，最终仍需观看成片。
