# 2026.10.14.1 通用维护包

这是 v0.1.2 接入预览新增的独立维护目录，不替换官方主程序，也不包含私人版的栏目、项目、声音资产或配置。旧版 `official-2026.10.12.1.patch` 保留历史用途，**不能**与本目录补丁叠加后直接升级私人实例。

## 已提供的通用修复

`redraw-four-inputs.patch` 针对官方提交 `cb8edf14b13c246797b6905dee5afaafce788d6f`：

- 核心分镜图网页重绘与 bridge 的默认四图总量一致，取消旧三图前端/请求模型限制。
- 当前画面、选中素材及自动场景一起计数；超过总量时明确报错。
- 勾选当前画面不再悄悄取消已选素材，恢复选项时不再截断第四张；上传超额素材保留到素材库，并提示手动调整选择。

本补丁默认总量仍是 **4**，不承诺任意模型支持 16 图。场景资产自身的设计选图、独立图片工作室、自动规划选图策略不在这份补丁的扩展范围内。

`plugins/ocv_community/maintenance_src` 包含两个可单独复用的通用模块：

- `frontend/src/imageReferenceCapacity.js`：选图、当前图和自动场景的合计计算；已由上述补丁接入。
- `backend/app/image_reference_limits.py`：按图像配置校验参考上限、同模型快照升级及总量校验。默认 4、可配置范围 1–16；范围是应用上限，实际能力必须以服务商文档或实测为准。**此模块作为宿主接入源码交付，上述四图补丁不自动接入其高级配置。** 作者若启用它，应同时接入配置 schema、保存/快照、最终渲染校验和前端，不可只放宽选择器。

## 核验与接入

```powershell
python tools/verify_maintenance.py --official-root "C:\Official-OCV"
python -m unittest discover -s tests
```

首条命令在临时目录校验精确基线、补丁及语法，不修改传入目录，不加载模型，不调用付费接口。它核验源码适配关系，不声称作品质量通过。
核验需要 Git、Node.js 和 OCV 使用的 Python 环境（含 Pydantic）。登记清单的安装器仍只使用 Python 标准库。

作者可在干净的固定版本源码中审查、应用补丁并构建前端。此目录不提供自动覆盖主程序的安装动作；原插件安装器仍只登记清单。官方目前缺少执行这些前后端扩展的完整插件钩子，不能把“清单出现”当作“功能已接入”。

## 本次官方更新核对

| 官方新增或调整 | 接入边界 |
|---|---|
| 云端/集群 H3 入口与批量选择 | 可选路由；不要静默替代其他配音流程，作品与服务配置由用户选择 |

## 开场状态问题的宿主建议

文字设计“充分”不能替代像素验收。建议把状态参考与身份图分开绑定，给出实体、部位、可见起点和引用文件指纹；起点和终点分别传给图片与视频。已完成的状态编辑经正式检查仍失败时，应提示补充状态资产，保留手动编辑/上传入口，避免自动重复付费重绘。

这里交付的是接口建议，**未宣称四图补丁已实现状态绑定或画面审核**。不降低已有审核，也不把失败图标成已通过。
